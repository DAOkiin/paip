# Политика имен и идентификаторов

## Именование файлов

- Имена файлов — `snake_case.md`, без пробелов и заглавных букв (кроме кодов аббревиатур вроде `temporal.md`).
- Ключевые файлы в `iterations` повторяют назначение без лишних префиксов: `scope.md`, `traceability.md`, `acceptance.md`.
- Для вложенных документов используем краткий и устойчивый идентификатор: `requirements.md`, `architecture.md`, `domain_model.md`.

## Идентификаторы требований

- Пользовательские истории: `US-XXX` (начинается с 1).
- Системные use case: `UC-XXX`.
- Нефункциональные требования: `NFR-XXX`.
- Ограничения/риск-условия: `RISK-XXX`.
- Acceptance criteria: `AC-XXX`.
- Архитектурные решения: `ADR-XXX`.

## Схема трассируемости

```
US/UC/NFR
   ├── iterations/*/selected_requirements
   ├── iterations/*/architecture + domain/event/data
   ├── iterations/*/traceability
   └── iterations/*/acceptance
```

## Нумерация внутри документа

- Номера в пределах секции нарастают по мере появления новой записи (не переиспользуются).
- Удаление строки из середины НЕ ломает историю: лучше добавить пометку `DEPRECATED`.
- Если история полностью вышла из актуальности — архивировать, а не переименовывать существующий ID.

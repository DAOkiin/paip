## Motivation
Зафиксировать PR-описание в git и закрыть ранее отмеченные риски по Query Catalog:
1) отсутствие runtime-emitted `query_id` correlation;
2) unbounded list queries, вызывавшие `QC-07` предупреждения.

## What changed
- Сохранено PR-описание как `git note` на коммит `0524eb8`.
- Добавлено runtime query observability:
  - `query_id`-логи в Store data-access методах (`src/paip/db.py`),
  - `query_id`-логи в debug raw SQL path (`src/paip/debug.py`).
- Введена реальная пагинация для list-query paths:
  - `Store.list_monitors(enabled_only=False, limit=200, offset=0)`
  - `Store.list_runs(monitor_id, limit=200, offset=0)`
  - `Store.list_notifications(monitor_id, limit=200, offset=0)`
- Добавлен paging-loop в scheduler для полного обхода enabled monitors страницами.
- Расширен CLI:
  - `paip monitor list --limit <int> --offset <int>`
- Обновлён Query Registry для `Monitor.List`, `Run.ListByMonitor`, `Notification.ListByMonitor`:
  - добавлены `limit/offset` params,
  - добавлена `contract.pagination`,
  - удалены `allow_unbounded*` исключения.
- Добавлены тесты:
  - пагинация `list_monitors`,
  - пагинация `list_runs`/`list_notifications`,
  - emission `query_id` логов через `caplog`.

## How to run
```bash
just qc-setup
just qc-validate
.venv/bin/python scripts/qc_validate.py --root . --policy query-catalog/policy.template.yaml --check-call-sites
bash scripts/qc_validate_ci.sh
just test
```

## CI impact
- QC validation остаётся обязательным и теперь проходит без `QC-07` предупреждений.
- Прод-зависимости не добавлялись.
- Изменения минимально инвазивны: поведение pipeline не изменено по бизнес-логике.

## Risks
- `git notes` не всегда автоматически пушится вместе с веткой; для переноса note нужен явный push refs/notes.

## Follow-ups
- При публикации ветки выполнить push notes (пример):
  - `git push origin refs/notes/*`
- После внедрения query_id correlation можно включать stricter drift checks (`--check-usage`, `--strict`) в CI поэтапно.

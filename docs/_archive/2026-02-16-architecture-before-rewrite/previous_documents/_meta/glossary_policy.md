# Политика продуктового глоссария

## Цель

Один термин — одно значение во всей документации, чтобы в разных артефактах не возникали расхождения.

## Базовые правила

- Если термин используется по-разному в технических и пользовательских документах, в `product/glossary.md` дается единственное определение.
- Новые термины из `research` добавляются через `product/glossary.md` только после согласования в `needs`/`user stories`.
- Все решения по терминологии фиксируются ссылкой на изменения в `doc_map`.

## Мини-структура записи

- Термин
- Определение (1–2 фразы)
- Пример из реальной истории
- Как связан с продуктом/системой

## Не добавлять в глоссарий

- Временные технические имена таблиц/сервисов.
- Аббревиатуры фреймворков без продуктового смысла (например, отдельные библиотеки), если они не влияют на пользовательскую ценность.

# Архитектура 2026-02-mvp

## Архитектурный контур

MVP строится как конвейер `Источники → Сбор → Проверка новизны → Отбор → Уведомления`.

```text
Источники
  └─ Коннекторы
      └─ Сборщик (schedule/manual trigger)
          └─ Нормализатор
              └─ Детектор новизны
                  └─ Роутер правил
                      ├─ История/хранилище
                      ├─ Уведомитель
                      └─ Дайджест-агрегатор
```

## Главные решения

- Конвейер и сценарии разделяются: источник может быть разный, но обработка идёт по общему пути.
- Уведомления опираются на уже проверенную новизну; повторяющиеся сигналы должны быть сводимы.
- Каждый сценарий имеет понятный жизненный цикл запуска: `включён` → `запущен` → `выполнен`.

## Что считаем обязательным в этой версии

- Конвертация разных источников в общий формат события.
- Режим ручного запуска и периодического запуска.
- Один основной канал доставки уведомлений.
- Логирование причины срабатывания для истории.

## Что оставляем позже

- Продвинутый NL-интерфейс и ассистированная сборка сценариев.
- Распределённая оркестрация и сложная observability.
- Многосторонняя интеграция с внешними BI/дашбордами.

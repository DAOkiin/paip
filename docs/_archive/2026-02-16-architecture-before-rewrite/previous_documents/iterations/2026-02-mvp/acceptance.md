# Acceptance Criteria 2026-02-mvp

## Общий критерий готовности

Итерация считается завершённой, если все P0 user stories и обязательные use cases воспроизводимо выполняются и есть история результатов в traceability.

## AC по user stories

- **AC-US-001:**  
  Пользователь может добавить городской мониторинг и получить: событие, уведомление, историю по этому сценарию с датами и источником.
- **AC-US-002:**  
  Пользователь получает единый список событий по склеенному источнику без ручного просмотра каждой площадки.
- **AC-US-004:**  
  Пользователь настраивает тему и получает только релевантные уведомления по этой теме, включая сводный режим.
- **AC-US-005:**  
  При изменении цены формируется сигнал с указанием нового значения и сравнения с прошлым состоянием.
- **AC-US-006:**  
  Изменение страницы отражается в истории с кратким пояснением, что именно изменилось.
- **AC-US-007:**  
  Пользователь получает дайджест по расписанию и может отличить его от одиночных сигналов.
- **AC-US-008:**  
  Пользователь может запустить сценарий вручную и получить результат в течение короткого времени.
- **AC-US-009:**  
  Любой сценарий уровня MVP редактируется без разработки: источник/порог/частота/режим уведомлений.

## AC по use cases

- **AC-UC-001:** система может собирать данные минимум из двух источников.
- **AC-UC-002:** один и тот же тип сигнала приводится к единому виду.
- **AC-UC-003:** дублирующие или уже известные сигналы не формируют лишних уведомлений.
- **AC-UC-004:** приоритетный сигнал и обычный сигнал имеют одинаковый путь маршрутизации с отдельными правилами фильтрации.
- **AC-UC-005:** каждый сигнал имеет запись в истории уведомлений.

## Приёмка команды/пользователя

- Смоук-сценарий 1: настроить монитор по городу и убедиться, что новый анонс приходит и есть история.
- Смоук-сценарий 2: изменить цену на тестовой странице и увидеть сигнал.
- Смоук-сценарий 3: вручную запустить сценарий и проверить ответный сигнал без планового расписания.

# A4 Project Canvas — 5 блоков

---

## Блок 1. Цель / Outcome + метрики (самый важный)

**Объём:** 3–5 строк максимум

Пиши в формате:

* **Зачем существует система**
* **Что она должна уметь делать стабильно**
* **Как понять, что она работает**

Пример формата (не текст, а структура):

* Цель: …
* Outcome: …
* Метрики:

  * …
  * …
  * …

---

## Блок 2. MVP Scope — In / Out

**Объём:** 2 колонки или просто два списка

**IN (делаем в MVP):**

* …
* …
* …

**OUT (осознанно не делаем):**

* …
* …
* …

💡 Важно:
Это **защита от расползания проекта**. Всё, что не влезло сюда — легально игнорируется.

---

## Блок 3. Use Cases (5–9 штук)

**Объём:** короткие глагольные формулировки, без деталей

Формат:

* Добавить источник
* Запустить сбор
* Сохранить версию страницы
* Извлечь текст
* Найти сущности
* Определить тренды
* Сравнить изменения
* Сформировать дайджест

💡 Правило:
**1 use case = 1 ценность**, а не техническая операция.

---

## Блок 4. Архитектура + Stack (очень сжато)

Это **не диаграмма**, а “mental model”.

Формат:

* Поток (стрелками или списком):

  ```
  Source → Orchestrator → Fetch → Extract → NLP → Trends → Storage → Output
  ```
* Ниже 5–7 ключевых технологий:

  * Language: …
  * Orchestration: …
  * Storage: …
  * Scraping: …
  * NLP: …

  * …

### Риски (3 штуки максимум)

* …
* …
* …


---

## Как этим пользоваться дальше

* Этот лист:

  * лежит перед глазами,
  * **не редактируется в коде**,
  * обновляется максимум раз в 1–2 недели.
* Если решение или задача **не укладывается ни в один блок** — это сигнал, что она сейчас не нужна.

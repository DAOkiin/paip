# Нефункциональные требования

## NFR-001: Достоверность

- У пользователя должна быть возможность видеть источник каждого уведомления.
- Для ключевых сигналов должен быть минимальный контекст «почему это пришло сейчас».

## NFR-002: Предсказуемость

- Для каждого сценария пользователь ожидает стабильного поведения по расписанию.
- Изменения поведения отмечаются заранее и объясняются в `open_questions`/`release_notes`.

## NFR-003: Контроль шума

- Система не должна засорять пользователя повторяющимися уведомлениями.
- Неповторные сигналы должны быть видимо отличимы от «без изменений».

## NFR-004: Прозрачность изменений

- Пользователь может просмотреть историю событий по сценарию.
- История должна быть доступна для проверки и повторной оценки.

## NFR-005: Отказоустойчивость

- Если один источник недоступен, остальные сценарии продолжают работать.
- Ошибки в одном конвейере не должны ломать всю систему.

## NFR-006: Удобство управления

- Любой сценарий уровня MVP настраивается без написания кода.
- Редактирование параметров должно быть обратимо без потери истории.

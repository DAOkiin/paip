# Глобальные Use Case (возможности системы)

Эти описания — про то, **что система должна уметь**, а не про конкретные задачи пользователя.  
Ниже сформирован портфель возможностей, из которых выбирается MVP-объём.

- **UC-001: Сбор информации из источников**
  - Система собирает релевантные данные из разных типов источников (новостные ленты, веб-страницы, API, репозитории/сообщества).
  - Поддерживает запуск по расписанию и ручной запуск для срочных случаев.

- **UC-002: Нормализация и единый формат**
  - Система приводит результаты к единой структуре: событие/сущность, источник, время, ключевые поля.
  - Это создаёт единое представление для пользовательского потока и последующей обработки.

- **UC-003: Выявление новизны**
  - Система сравнивает новые данные с историей и определяет, что действительно новое или изменилось.
  - Управляет повторными публикациями и обновлениями без дублирования.

- **UC-004: Многоуровневый фильтр и маршрутизация**
  - Система применяет правила важности и приоритетов.
  - На уровне маршрутизации формирует «тихий» и «чрезвычайный» поток уведомлений.

- **UC-005: Нотификации и история уведомлений**
  - Система отправляет результаты в заданные каналы и ведет историю по каждому событию/темы/городу.
  - Поддерживает сводный и детальный режимы.

- **UC-006: История источника и доказательной базы**
  - Система хранит, из каких источников пришла информация и какие шаги отборa происходили.
  - Для спорных/важных сигналов должна быть возможность отобразить обоснование.

- **UC-007: Отслеживание изменений страниц**
  - Система периодически контролирует выбранные страницы и регистрирует изменения по значимым частям.
  - Важно не просто фиксировать факт изменения, а показать, что именно изменилось для пользователя.

- **UC-008: Отслеживание цен и пороговых отклонений**
  - Система считывает цену/показатели по расписанию, держит ряд изменений и формирует сигналы о пороге или резком изменении.

- **UC-009: Отслеживание активностей репозиториев и проектов**
  - Система фиксирует новые релизы, активности и упоминания по указанным репозиториям/поисковым параметрам.
  - Сигналы не привязаны к внутреннему расписанию пользователя — обновления формируются в единый поток.

- **UC-010: Поиск и тематическая группировка**
  - Система объединяет материалы по теме, городу, типу события и источнику.
  - Поддерживает пересечение пересечений: один материал может относиться к нескольким темам.

- **UC-011: Экспорт/синдикация результата**
  - Система может передавать сформированный поток во внешние потребители (канал, чат, файл, API-выход).
  - Экспорт выполняется в согласованном формате, чтобы потребитель не терял контекст.

- **UC-012: Наблюдаемость и аудит качества**
  - Система умеет отчитываться о своих ошибках, пропусках и задержках.
  - По каждому этапу должен быть минимальный уровень объяснимости.

- **UC-013: Эволюция сценария через NL-формулировку** (позже)
  - Система принимает зафиксированные, ограниченные формулировки пользователя и инициирует подготовленный сценарий мониторинга.
  - Нужны guardrails и подтверждение перед исполнением.
